# 作業報告の実費記録

作業報告の登録フォームで、項目名と金額（円、整数）を最大50件入力できます。実費がない報告は従来どおり登録できます。報告と実費は同じDBトランザクションで保存し、写真登録に失敗した場合の報告取り消しでは未請求実費も取り消します。

管理者の「実費管理」で物件番号・作業日・項目・金額を一覧表示し、未請求・請求作成後・公開後のいずれでも項目・金額を訂正できます。訂正理由は必須です。作業者は実費を登録・閲覧できますが、登録後の金額修正は管理者だけです。顧客は自分の物件の作業報告に紐づく実費だけ閲覧できます。コミュニケーション画面の作業報告に項目名・金額・実費合計を付記し、請求公開前の実費も目安として表示します。修正・登録権限は付与しません。

請求情報の作成・公開・撤回は `docs/customer-contract-billing.md` を参照してください。実費の訂正は有効な下書き・公開済み請求情報にも同期し、撤回済み請求は変更しません。税区分、税額計算、請求締め日は扱いません。

`report_expenses.billed_at`は請求への紐付けを管理するサーバー専用列です。項目・金額の訂正は管理者専用の `correct_report_expense` RPCで行います。直接のクライアント更新権限は廃止し、理由なしの変更を防ぎます。削除・報告や請求の付け替えは今回の訂正に含めません。

公開順序：`20261018230614_report_expenses.sql`を適用し、テーブルのRLSと登録RPCを確認した後、フロントエンドを公開します。既存の報告・写真のレコードは変更しません。

実費・請求情報の表示には「請求情報は目安であり、金額は変動する場合があります」を小さな薄い文字で併記します。

顧客向け実費表示の公開時は `20261020100826_customer_report_expenses.sql` を先に適用し、その後フロントエンドを公開します。他顧客・作業者・管理者の権限は既存どおりで、請求下書きの非公開も維持します。

## 実費の訂正と編集履歴

本アプリは顧客との情報伝達のために料金の目安を共有します。契約責任・正式な請求書発行・入金管理は別のレイヤーで扱い、本アプリで実費を訂正してもローカルアプリの正式請求書は自動変更しません。

「実費管理」の「実費を訂正」から、項目・整数円の金額・理由（1〜2000文字）を保存します。管理者のみ操作でき、停止・削除・認証失効を最新の権限で確認します。表示時の項目・金額がすでに変更されている場合は上書きせず、再読込を求めます。

実費・現在有効な請求明細・各編集履歴は1トランザクションで保存します。請求作成・公開・撤回と同じアドバイザリロックを使い、二重請求や履歴との不整合を防ぎます。撤回済み請求はそのまま保持します。下書きを再作成して明細が入れ替わっても、請求情報の訂正履歴は残ります。

履歴には変更前後・日時・操作者ID・理由を保存します。顧客は自分の物件の実費履歴と、自分の公開済み請求の訂正履歴だけ閲覧できます。職員名・利用者名は表示しません。通常クライアントは履歴の追加・変更・削除ができません。

コミュニケーション欄では1回の実費訂正につき「報告内容を訂正しました。対象：該当の作業報告を開く」を表示します。リンク `#report-<報告ID>` から対象物件・作業報告を表示でき、報告と請求情報の下部に折りたたみの実費編集履歴を表示します。報告作成時点から顧客が実費を閲覧できる現行仕様のため、請求情報が下書きでも実費自体の訂正は通知します。請求下書きの情報は通知・顧客向け履歴に含めません。

公開時は `20261028224011_expense_corrections.sql` を先に適用し、その後フロントエンドを公開します。旧画面は直接更新権限がなくなるため、公開後は再読み込みして利用します。既存の訂正履歴は遡って作成しません。点検チェックリストや報告本文・写真全体の編集機能とは独立した、実費訂正の変更です。
